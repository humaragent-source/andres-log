Duress-Aware Wallet Security Standard

A feature layer for self-custody that survives coercion — without pretending a gunman can’t open your phone.

For engineers & partners · Examples limited to EtherFi, RedotPay, Cast, Tornado Cash · Editable working draft

1. Executive summary

Self-custodial wallets give users key control but almost none of the operational brakes people expect from banks: withdrawal limits, cool-downs, trusted approvers, or a credible answer to physical force. Face ID opens the real vault for anyone who can press a phone to the owner’s face; once funds leave through a mixer, recovery is effectively gone.

This proposal defines an adoptable feature layer — not one rigid UI — built around a second password that opens a decoy vault, geofenced secondary authentication, time-locks and multi-sig on large transfers, optional app masking, and an optional panic-drain path.

💡
The thing a gunman can force out of you stops being the real vault. Same username; a second password opens a believable decoy holding a substantial but non-devastating sum. Logout + the original password restores the real vault.

2. Problem statement

Retail banking and card rails routinely expose daily limits, holds, and dispute paths. Hot self-custody and spend rails (EtherFi-class wallets, RedotPay-class cards) settle immediately once a signature broadcasts. Biometrics map 1:1 to full spending authority. Coercion + Face ID + mixer laundering (historically exemplified by Tornado Cash) collapses recovery.

⚠️
Masking the icon is not enough. Disguise must survive the full interaction — notifications, biometric sheets, balances, send flow — or it collapses under shoulder-surfing. Treat masking as an end-to-end state (Cast-grade UX), not a skin.

3. Solution overview

Under duress away from home, the attacker gets a vault that looks real and can move a calibrated sum. The real vault never unlocks.

Attacker demands unlock → Face ID → Secondary password → Decoy vault → ~$3K moves → Real vault untouched
ℹ️
Inside the home geofence, products may relax secondary prompts for daily spend. Outside it, biometric is only a device gate — the password chooses which vault opens.

4. Feature breakdown

Duress password & decoy calibration

Same identity. Primary password → real vault. Duress password → decoy vault (~$3,000 illustrative default for moderate users). Logout + primary restores real.

Swipe for more →

TierSuggested decoy (USD)Notes
Quiet / new$500 – $2,000Believable hot wallet; survivable loss
Moderate activity$3,000 – $8,000Default band; short-inspection plausible
High-profile / large history$15,000 – $50,000 (≤5–10% of hot funds)Low decoy fails against known wealth

Default funding: static (or rarely reviewed). Optional slow drift only — never auto-mirror real deposits. Skip decoy if the attacker likely already knows exact holdings.

Biometric gating

Face ID alone is insufficient outside a trusted context. Outside the geofence, biometric unlocks the device gate only; a password selects the vault. Breaks the failure mode where a forced face equals the full treasury.

Geofence rules
  • Configure home / trusted radii as a policy object (not one hard-coded map).
  • Outside radius: secondary password required for vault selection.
  • GPS spoofing is a known hole — pair with integrity signals or fail closed (see threat matrix).
Transfer safeguards
  • 24h time-lock on transfers above an illustrative $1,000 threshold when outside the fence.
  • Multi-sig / trusted approver for the same class of sends (see §5).
  • Optional allowlists for known destinations to reduce false friction.
  • Emergency override paths must be rare, audited, and rehearsed — never a silent bypass.
App masking

Wallet presents as a mundane app (e.g. gym tracker) until a reveal code / gesture opens the real UI. Must survive notifications, biometric prompt copy, and deep links — not just the home-screen icon. Wrong code → full mundane interaction. Biometric fallback must not flash wallet chrome on the disguise shell.

Panic-drain layer (optional)

A third password / gesture can move real hot funds to a pre-set burner / deep cold address while a decoy session continues for cover. High mistype risk — require Simulation rehearsal. Keep optional.

5. Multi-sig approver models

Safety 1–5 = harder for a coerced user alone to move large funds. Ease 1–5 = less daily friction. Relative brainstorm scores, not audits.

Recommended default for partners: Hybrid. Highest practical safety with a fallback when the human is unreachable. Delayed self-approval is easiest to ship but weakest against a patient attacker.
