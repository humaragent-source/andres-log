9. In-practice flow trees

Each branch: condition → UI state → next. Amber flags mark where users get stuck or confused.

(a) Home · normal login → real vault

IF inside geofence AND biometric OK AND (no PW required OR primary PW)
→ UI: Real vault home (true balances)
→ NEXT: normal send / card spend
⚠️
Stuck risk: user forgot they enabled “always ask password even at home.”

(b) Outside · Face ID · original password → real vault + brakes

IF outside geofence AND biometric OK
→ UI: Secondary password sheet (no vault hint)
IF password == primary
→ UI: Real vault
→ NEXT: sends ≥ threshold enter time-lock and/or approver queue
⚠️
Stuck risk: user thinks Face ID failed. Copy must say “password required away from home.”

(c) Outside · Face ID · decoy password → decoy vault

IF outside geofence AND biometric OK AND password == duress
→ UI: Decoy vault (calibrated balance, plausible history)
→ NEXT: decoy sends look instant; hide real-vault time-lock chrome (avoid a tell)
⚠️
Stuck risk: real-vault notifications leaking. Suppress or rewrite while a decoy session is active.

(d) Transfer above threshold · outside geofence

IF real vault AND outside fence AND amount ≥ threshold
→ UI: “Pending · unlocks in 24h” + Approver notified
→ NEXT: wait · cancel · optional speed-up via second factor
⚠️
Stuck risk: urgent legitimate pay (rent, medical). Show clear cancel + path to adjust threshold later — never a silent infinite wait.

(e) Approver unreachable → fallback

IF approval pending AND approver timeout
→ UI: Fallback banner
→ hybrid → escalate to service · person-only → extend lock / try next enrolled contact · delayed-self → continue countdown
⚠️
Stuck risk: silent failure. Always show countdown + who was pinged — without revealing that a decoy mode exists.

(f) Panic-drain trigger

IF panic gesture/code entered (optional)
→ UI: brief confirm (or zero-confirm if configured for true emergency)
→ NEXT: move real hot funds to pre-set cold/burner path; decoy session may continue for cover
⚠️
Stuck risk: mistype under stress. Require Simulation rehearsal; treat as irreversible without a recovery ceremony.

(g) App masking · wrong reveal code

IF masking ON AND launch/reveal code wrong
→ UI: Mundane app (gym tracker / notes) — full interaction
→ NEXT: no wallet chrome, no crypto notifications
⚠️
Stuck risk: forgotten reveal code. Recovery must not show “Forgot wallet password?” on the disguise shell.
🗺️
Quick tree: Launch → (masking wrong → mundane) else → inside fence → real vault; outside → Face ID → password sheet → primary (real + brakes) / duress (decoy) / panic code (drain + optional cover).

10. Positioning

Ship this as an adoptable feature layer, not one mandatory UI or one shared secret scheme. Uniform behavior across every wallet is predictable — and therefore attackable.

🧩
Fragmentation aids security. Different decoy defaults, prompt copy, and threshold UIs raise the cost of a rehearsed attack script. Partners share a vocabulary; they do not freeze into one monoculture.

11. Open risks

  • High Demand real password after decoy transfer — no control cell covers this; calibration + training only.
  • High GPS / location spoofing — can skip outside-fence rules; need integrity or fail-closed.
  • High Coercion at home — geofence brakes don’t fire; duress password + believable decoy carry the load.
  • High Seed-phrase social engineering — mostly out of band for this feature layer.
  • Medium Decoy-amount mis-calibration — too small invites escalation; too large is real loss.
  • Medium Approver / multi-sig custody — new social-engineering and outage surfaces.
  • Medium Notification & metadata leaks — widgets, email, chain analytics can betray the real vault.
  • Medium AML / KYC perception — masking + duress can look like evasion; frame as personal safety, distinct from mixer semantics.
  • Low Recovery after duress use — solvable with a safe rotate ceremony; easy to rush or skip.
  • Low Panic-drain mistype — rare if optional + rehearsed; severe if not.

12. Phased roadmap

1

Formalize vault separation, geofence policy object, threshold / time-lock semantics, coercion scenarios (home vs away).
2
Reference-wallet prototype
One open reference: duress password, decoy vault, geofence gate, masked UI shell, Simulation mode.
3
Neobank / card pilot
Partner with a spend rail (RedotPay-pattern) and/or self-custody product (EtherFi-pattern) on real send flows.
4
Publish vocabulary
Release the four terms; keep UI and defaults plural across adopters.

13. Appendix · Glossary

Decoy vault
Isolated balance and history opened by the duress password; must not unlock real vault keys.
Duress password
Second credential for the same username that opens the decoy vault.
Geofence policy
Set of trusted places and the rules that apply when the device is outside them.
Transfer threshold
Amount above which time-lock and/or multi-sig approval is required (illustrative default $1,000 outside the fence).
Multi-sig hook
Integration point to a human co-signer, rotating list, or third-party policy service.
App masking
Full-interaction disguise as a mundane app until a reveal code opens wallet UI.
Panic-drain
Optional third secret that moves real hot funds to a pre-set burner / deep cold path.
Simulation mode
Onboarding (and quarterly) rehearsal where no real funds move.
Time-lock
Mandatory delay before an above-threshold transfer can broadcast.
Feature layer
Adoptable kit of behaviors and vocabulary — not a single rigid standard UI.
